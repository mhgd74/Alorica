# Alorica Booking System

نظام حجز مواعيد النقل لشركة **Alorica** — واجهة عصرية بالإنجليزية بالكامل (LTR)، مع توزيع تلقائي على الحافلات، وسير عمل موافقات بين الموظف والتيم ليدر، وتقارير Excel قابلة للمشاركة والطباعة.

---

**ملاحظات:**
- اسم المستخدم `admin` محجوز ولا يمكن استخدامه عند إنشاء حساب جديد.
- الأدمن **لا** يعدّل أو يحذف الحجوزات — وظيفته المراجعة والطباعة والتصدير فقط.
- لا يمكن للمستخدم الموافقة على طلب أنشأه بنفسه.
- التيم ليدر هو أيضاً موظف، وله شاشة حجز خاصة به (التبديل بين `Dashboard` و `My bookings` من الشريط العلوي). تعديلاته على حجزه **تُطبَّق فوراً** لأن سلطة الموافقة بيده، لكنها تُسجَّل في سجل النشاط وتُبلَّغ لباقي التيم ليدرز.
- يتوقف زر الطباعة/التصدير عن العمل خارج دور الأدمن.
- ⚠️ **تعارض يحتاج قراراً:** زر `Auto-assign buses` متاح للأدمن داخل تبويب `Buses` بلا قيد، بينما القاعدة المتفق عليها تقصر التوزيع التلقائي على التيم ليدر. التوثيق هنا يصف الواقع لا القاعدة.

## الشاشات

### شاشة الموظف
- **نموذج الحجز:** الاسم، رقم الموظف، الاتجاه (Arrival/Departure)، الوقت، التاريخ، ونقطة الاستلام من قائمة ثابتة (`ALL_POINTS`).
- **My Bookings:** بطاقات الحجوزات مع زر تعديل، وشارة تحذير عند اقتراب الموعد (أقل من ساعة).
- **الإشعارات (الجرس):** طلبات التعديل الواردة للموافقة/الرفض، وتبقى غير مقروءة حتى يتخذ قراراً.

### شاشة التيم ليدر
- **Review Bookings:** مراجعة الحجوزات، تعديل/حذف، `Auto-assign buses`، وزر `Send to Admin` لإرسال الشيت.
- **Change Requests:** الطلبات المعلّقة (من الموظفين أو الموجّهة لهم) + **Emergency override** + **سجل النشاط (Activity log)**.

### شاشة الأدمن
- **Bookings:** إحصائيات، بحث وفلترة (نص + نطاق تاريخ)، جدول مجمّع حسب اليوم، وتصدير/طباعة/مشاركة. ويظهر تنبيه بعدد الحجوزات التي ما زالت لدى التيم ليدر ولم تُرسَل بعد.
- **Change Requests:** نفس تبويب التيم ليدر لكن بصلاحية قراءة.
- **Buses:** إضافة/حذف الحافلات وتعديل السعة اليومية، مع زر `Auto-assign buses` لإعادة التوزيع.
- **Users:** إنشاء المستخدمين وتحديد الدور عند الإنشاء (`user` / `teamlead`)، النسخ الاحتياطي والاستعادة (JSON). أدوار المستخدمين الحاليين للعرض فقط ولا تُعدَّل بعد الإنشاء.
- **Password Requests:** طلبات "نسيت كلمة المرور" وإصدار كلمات مرور مؤقتة.

## سير العمل

### دورة حياة الشيت
`Draft` → `Sent to admin` → `Locked after printing`

- التيم ليدر يُرسل الشيت إلى الأدمن (يُمنع الإرسال بعد القفل).
- طباعة الأدمن تقفل الشيت نهائياً.
- يمكن للأدمن إرجاعه إلى `Draft` (`Send back to team leader`) لتمكين تعديلات إضافية.

### قاعدة الساعة الواحدة
قاعدة واحدة تحكم كل تصرّف ذاتي من الموظف على حجزه (تعديل أو إلغاء):
- **ساعة أو أكثر قبل الموعد:** يُطبَّق التغيير فوراً.
- **أقل من ساعة:** يتحول إلى طلب موافقة إلى التيم ليدر.
- تُفحص **الحالة الراهنة والقيم الجديدة معاً**، فلا يمكن التحايل بنقل الحجز إلى وقت قريب.

### تعديلات الإدارة
التيم ليدر يطلب التعديل → إشعار للموظف → قرار الموظف → التطبيق عند الموافقة → إشعار عكسي للتيم ليدر.

### المسارات المؤقتة
| المسار | المدة | عند الانتهاء |
|--------|-------|--------------|
| كلمة المرور المؤقتة | 24 ساعة | تفقد صلاحيتها |
| طلب التعديل المعلّق | 48 ساعة | يُلغى مع إخطار التيم ليدر |

**قيد:** يمنع إنشاء أكثر من طلب تعديل معلّق واحد لنفس الحجز.

## توزيع الحافلات
- **الشركة لا تمتلك حافلات** — تُستأجر من مزوّدين (مثل سويفل) بناءً على الحجوزات.
- التوزيع يملأ الحافلات بترتيب موعد الحجز، ومن لا يجد مقعداً ينتقل إلى **Waitlist** (يظهر بالأحمر).
- عند إلغاء حجز، يُرقّى أول المنتظرين تلقائياً ويُبلَّغ التيم ليدر بأن المقعد تحرّر.
- **تعديل حجز لا يعيد التوزيع:** الموظف يبقى في نفس المركبة المستأجرة.
- تعتمد الدقة على نقاط الاستلام الثابتة `ALL_POINTS`؛ لذلك أُزيل تحديد الموقع التلقائي (Geolocation) لأن الإحداثيات الحرة كانت تُفسد منطق التجميع.

## ملف Excel
- شيت **Summary** أولاً: ملخص لكل يوم (الحجوزات، الموظفين، توزيع الحافلات، قائمة الانتظار) + صف إجمالي.
- ثم **شيت لكل يوم**: Employee Name، Employee ID، Booking Time، Pickup Point، Type، **Bus**.
- ترويسة بألوان Alorica، صف إجمالي، AutoFilter، وأعمدة بعروض مناسبة.
- اسم الملف: `Alorica_Bookings_<date>.xlsx` أو `Alorica_Bookings_<from>_to_<to>.xlsx` عند فلترة التواريخ.
- التصدير يعمل على النتائج المفلترة.

## المزامنة والعمل دون إنترنت
- كل جهاز يحتفظ بنسخة في `localStorage` للعمل الفوري ودون اتصال.
- التعديلات المحلية تُدفع إلى الخادم قبل جلب الحالة الجديدة (`syncFlush` قبل `pull`)، فلا تضيع عند عودة الاتصال.
- لا يتحول النظام إلى `Online` إلا بعد إفراغ طابور التعديلات المعلّقة.
- `GET /api/rev` يُفحص دورياً (كل 3 ثوانٍ) وعند عودة التركيز إلى النافذة.
- جميع المكتبات مستضافة محلياً في `vendor/` (بلا CDN) + `manifest.json` و`sw.js` للعمل دون اتصال والتثبيت.

## التقنيات
React 18 (UMD) · Babel Standalone (ترجمة داخل المتصفح) · Tailwind CSS · Lucide · xlsx-js-style · WebCrypto (PBKDF2-SHA256) · Node.js HTTP server · `node:sqlite` · Supabase (Postgres).

> التشفير (`WebCrypto`) يتطلب سياقاً آمناً: HTTPS أو `localhost`.

## التشغيل محلياً
```powershell
node server.js
```
ثم افتح `http://localhost:3080`.
HTTPS على المنفذ `3000` يعمل فقط إذا وُجد `certs/server.key` و`certs/server.crt`.

## النشر
- **Vercel:** ينشر تلقائياً عند الدفع إلى GitHub. `vercel.json` يعيد توجيه كل المسارات إلى `index.html` — **وهذا يحتاج تعديلاً** لاستثناء `/api/*` عند إضافة الخادم.
- **Supabase:** الترحيل قيد التنفيذ. الجداول المطلوبة: `items` (الحالة المشتركة) و`sync_meta` (عدّاد المراجعة) والدالة `apply_sync_ops()`.
